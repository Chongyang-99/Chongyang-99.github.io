GigaWorld-Policy: An Efficient Action-Centered World-Action Model — 2026

2026-05-31 · 原文

摘要

GigaWorld-Policy 提出了一种以动作为中心的 World-Action Model (WAM) 设计范式。核心思路是将 WAM 分解为两个子任务：动作预测与动作条件视频生成。通过因果注意力掩码设计，确保未来视频 token 不会影响动作 token 的生成，使得视频生成在推理时可以完全跳过。这种设计让 GigaWorld-Policy 在保持训练阶段视频监督优势的同时，推理速度达到 Motus 的 9 倍（360ms vs 3231ms）。真实机器人实验中，GigaWorld-Policy 取得 83% 的成功率，显著超过 Motus (76%) 和 pi0.5 (69%)。

一、Motivation

WAM 的核心假设是：让模型同时学习预测未来画面和生成动作，可以迫使模型学会更深层次的物理理解，从而提升策略质量。这个假设已经被 PAD、Motus 等前序工作验证。但现有 WAM 面临一个尴尬的效率瓶颈：推理时必须同时生成视频和动作，导致延迟极高。

GigaWorld-Policy 的核心洞察是：视频生成的价值在于训练阶段提供额外的梯度信号，而不在于推理阶段真的需要"想象未来"。如果能在架构层面保证"视频 token 不影响动作 token 的分布"，那么推理时就可以安全地跳过视频生成，同时保留训练时的收益。

这种设计需要解决一个关键的架构问题：如何在同一个模型里让视频和动作共享特征学习，同时又保证信息流的单向性——动作可以影响视频（因为视频是动作条件的），但视频不能影响动作。

二、方法详解

2.1 Action-Centered 设计

GigaWorld-Policy 将 WAM 的联合建模分解为两部分：

  • 动作预测：给定历史观测，直接预测未来动作 chunk，这是推理时唯一需要的部分
  • 动作条件视频生成：给定历史观测和预测的动作，生成对应的未来视频帧，仅在训练时使用

这种分解的关键在于明确了因果关系：动作决定了世界的变化，而不是反过来。视频生成作为一个辅助任务，通过反向传播为共享的编码器提供额外的物理理解信号。

2.2 因果注意力掩码

为了实现信息流的单向性，GigaWorld-Policy 设计了特殊的因果注意力掩码。在 Transformer 的 self-attention 中：

  • 动作 token 只能 attend 到历史观测 token 和自身，不能看到未来视频 token
  • 视频 token 可以 attend 到所有历史 token 和动作 token

这种非对称的注意力模式确保了一个重要性质：无论是否计算视频 token，动作 token 的输出分布完全相同。因此推理时可以安全地丢弃视频分支，不会改变动作的预测结果。

2.3 推理时跳过视频生成

由于因果掩码的保证，推理时模型只需要处理历史观测和动作 token，视频相关的计算全部跳过。这带来了巨大的加速：从 Motus 的 3231ms 降低到 360ms，加速比约 9 倍。同时，由于训练时视频监督仍然存在，模型的物理理解能力不会退化。

2.4 未来预测步长消融

GigaWorld-Policy 还研究了训练时视频预测的粒度问题。实验发现适度的预测步长 (stride 12) 效果最好——不预测未来画面 (stride = 0) 会导致性能从 83% 大幅降低到 65%，而预测过于密集的未来帧反而引入噪声。

三、实验结果

在速度方面，GigaWorld-Policy 的推理延迟仅 360ms，相比 Motus (3231ms) 快了约 9 倍。这个加速完全来自于推理时跳过视频生成，没有任何近似或压缩。

在真实机器人任务上，GigaWorld-Policy 达到 83% 的成功率，超过 Motus (76%) 和 pi0.5 (69%)。在 RoboTwin 仿真环境中，clean 设置下达到 87%。

消融实验清晰地展示了视频监督的价值：完全去掉未来预测后，性能从 83% 骤降到 65%。但预测步长的选择也很关键——stride 12 的适度预测显著优于逐帧密集预测，说明模型需要的是"粗粒度的物理理解"而非"精确的像素重建"。

四、总结

GigaWorld-Policy 通过因果注意力掩码实现了 WAM 中视频分支的"训练时参与、推理时跳过"，在不损失策略质量的前提下将推理速度提升 9 倍。它证明了 WAM 中视频生成的核心价值不在于推理时的"想象"，而在于训练时提供的物理理解信号。Action-centered 的设计范式为 WAM 的实际部署扫清了延迟障碍。

五、Insight

训练时的视频监督远比推理时的想象重要。

GigaWorld-Policy 最深刻的贡献不是具体的架构设计，而是对 WAM 价值机制的澄清：视频生成之所以能提升策略质量，核心原因是它在训练阶段为编码器提供了物理世界的梯度信号（强制模型理解"动作导致什么变化"），而推理时模型已经内化了这些物理知识，不再需要显式地"看到"未来画面。这个发现有深远的架构启示——未来的 WAM 设计应该把精力放在如何设计更好的训练时辅助任务上，而不是如何在推理时更高效地生成视频。

六、Q&A

Q1: 因果掩码如何保证跳过视频不改变动作分布？

关键在于注意力的信息流方向。在 Transformer 的 self-attention 中，动作 token 的输出只取决于它能 attend 到的 token。因果掩码确保动作 token 只能看到历史观测和自身，完全看不到视频 token。这意味着无论视频 token 是否存在、其值是什么，动作 token 的 attention 输出完全不变。因此跳过视频分支不会影响动作的条件概率分布 $p(a|o_{1:t})$。

Q2: 为什么 stride 12 比逐帧预测效果更好？

逐帧密集预测引入了大量冗余的像素重建任务，迫使模型花费容量去记住帧间的微小差异（光照变化、阴影抖动等），这些对控制毫无帮助。stride 12 的稀疏预测让模型聚焦于"跨越较大时间跨度的状态变化"，这恰恰是控制所需要的物理理解——物体位移、接触变化、任务进展等宏观动力学信号。

Q3: 与 Fast-WAM 的区别是什么？

两者的出发点相似（推理时不生成视频），但实现路径不同。Fast-WAM 直接在推理时截断视频生成分支，依赖经验观察来验证截断的安全性。GigaWorld-Policy 则从架构层面通过因果掩码提供了数学上的保证：动作分布与视频分支无关。此外，GigaWorld-Policy 强调了"action-centered"的分解视角，将视频生成明确定义为动作条件的辅助任务。

Q4: 9 倍加速是否足够满足实时控制需求？

360ms 对于典型的桌面操作任务（控制频率 3-10 Hz）基本满足需求，但对于高频控制场景（如灵巧手操作、动态抓取）仍然偏高。进一步的加速可能需要模型蒸馏、量化或者更激进的 token 压缩。不过相比 Motus 的 3231ms，GigaWorld-Policy 至少让 WAM 从"不可部署"变成了"可以部署"。

Q5: 这种设计能否扩展到更长的规划任务？

当前的 action-centered 设计主要针对短程操作（单个 action chunk 对应几十帧的时间尺度）。对于需要长程规划的任务（如多步装配），可能需要在高层引入显式的目标规划模块，而将 GigaWorld-Policy 作为低层的技能执行器。因果掩码的设计原则（信息流单向性）在分层架构中依然适用。
